# Scope Gate

## what it is

The scope gate (`utils/scope_gate.py`) is a framework-side backstop the
operator arms via the REPL (`scope on <handle>`). State is persisted to
`scope/.armed_packet_scope.json` (mtime-checked every call, so REPL changes
apply inside a running Brain). Arming is deliberately NOT exposed as an
`@framework_tool` so the secretary can never toggle it.

## how it works

Every traffic-sending tool raises `ScopeGateError` on a blocked target. The
gate checks the armed scope file's mtime on every call — changes made in
the REPL take effect immediately inside a running Brain sidecar. The gate
covers all HTTP (gated_get, gated_request, session_get, session_post,
session_upload), all brute-force tools (ffuf, hydra, sqlmap), nmap/masscan,
and Metasploit dispatches.

## scope file format

`scope/.armed_packet_scope.json` — a JSON file with allowed targets (IPs,
CIDR ranges, hostnames) and optionally ports. The file is operator-authored
or generated by the REPL `scope on` command. See `scope/lab_local-lab.json`
for an example.

## where it enforces

- **Bridge lane** (OWUI `framework_run_tool` / gateway `/tools/execute`):
  every tool dispatch goes through the gate.
- **execute_code lane** (Jupyter kernel): the gate fires on every
  traffic-sending call inside the kernel — identically to the bridge. The
  kernel does not bypass the scope gate.
- **REPL lane** (`tool_repl.py`): same enforcement — the REPL calls the
  same tool functions.
- **In-process fallback** (`daharness/executor.py`): when the Brain socket
  is down, tools run in-process with the same scope gate check.

## what it is NOT

The gate is never the legal basis, never a substitute for the agent's own
scope check. Default: NOT armed; nothing authorized until confirmed. The
agent must verify each action against documented scope before execute and
at every new target or changed objective, gate armed or not. Reachability
is not permission.
